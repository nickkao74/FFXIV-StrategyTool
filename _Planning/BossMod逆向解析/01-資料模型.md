# 01 — BossMod 的資料模型

本篇是讀懂任何一個 BossMod module 所需的基礎詞彙。全部結論都可回溯到插件原始碼行號。

---

## 1. 座標系

`BossMod/Util/WPosDir.cs`

```csharp
public readonly struct WPos(float x, float z)   // 只有 X / Z 兩軸,Y(高度)一律忽略
public readonly struct WDir(float x, float z)
```

- FFXIV 世界座標是三維,但 BossMod 全程只用 **X(東西)** 與 **Z(南北)** 兩軸。
- `+X` = 東,`+Z` = **南**。(這點很重要:遊戲內小地圖的「上」是北,對應 `-Z`。)
- 場地中心不是原點。朱雀場地中心是 `new WPos(100f, 100f)`,不同副本各有各的中心。

> 每個 module 都會在主類別裡宣告 `ArenaCenter`,先找到它再談任何座標。

## 2. 角度慣例

`BossMod/Util/Angle.cs`

```csharp
public static Angle FromDirection(WDir dir) => new(MathF.Atan2(dir.X, dir.Z));
public readonly WDir ToDirection() { var (sin, cos) = SinCos(Rad); return new(sin, cos); }
```

`ToDirection()` 回傳 `(sin θ, cos θ)` 當作 `(X, Z)`,所以:

| 角度 | 方向向量 (X, Z) | 方位 |
|---:|---|---|
| `0°` | (0, +1) | **南** |
| `90°` | (+1, 0) | 東 |
| `180°` | (0, −1) | **北** |
| `−90°` (=270°) | (−1, 0) | 西 |

**BossMod 的 0° 是南,順時針為正。** 這與一般直覺(0° 朝北)差了一個鏡射,
不是單純加 180°,轉換公式見 `03`。

常用常數(`Angle.cs:15-16`),注意它們刻意帶了千分之幾度的偏移以避開邊界判定:

```csharp
AnglesIntercardinals = [-45°, +45°, +135°, -135°]   // 索引 0,1,2,3
AnglesCardinals      = [-90°,   -0°,  180°,  +90°]   // 索引 0,1,2,3 = 西,南,北,東
```

換算成方位:`Intercardinals[0]`=西南、`[1]`=東南、`[2]`=東北、`[3]`=西北。

## 3. AOEShape — 形狀詞彙

`BossMod/BossModule/AOEShapes.cs`。所有形狀都是「以某個原點 + 某個朝向」定義的:

| 類別 | 建構參數 | 意義 |
|---|---|---|
| `AOEShapeCircle` | `(radius)` | 圓 |
| `AOEShapeDonut` | `(innerRadius, outerRadius)` | 甜甜圈 |
| `AOEShapeCone` | `(radius, halfAngle, directionOffset)` | 扇形。**`halfAngle` 是半角**,`45°.Degrees()` = 總張角 90° |
| `AOEShapeDonutSector` | `(inner, outer, halfAngle, offset)` | 扇環 |
| `AOEShapeRect` | `(lengthFront, halfWidth, lengthBack, offset)` | 矩形。**`halfWidth` 是半寬**,原點在「前後長度」的分界處 |
| `AOEShapeCross` | `(length, halfWidth, offset)` | 十字 |
| `AOEShapeTriCone` | `(sideLength, halfAngle, offset)` | 三角錐(直邊,非弧邊) |
| `AOEShapeCapsule` | `(radius, length, offset)` | 膠囊 |
| `AOEShapeArcCapsule` | `(radius, angularLength, orbitCenter)` | 沿圓弧掃過的膠囊 |
| `AOEShapeCustom` | 多邊形布林運算 | 複雜場地 |

> **反覆踩到的坑:`halfAngle` 與 `halfWidth` 都是「一半」。**
> `new AOEShapeRect(41f, 10f)` 是長 41、**寬 20** 的矩形,不是寬 10。

## 4. AOEInstance — 一次實際的 AOE

`BossMod/Components/GenericAOEs.cs:7`

```csharp
public struct AOEInstance(
    AOEShape shape,        // 形狀
    WPos origin,           // 世界座標原點
    Angle rotation,        // 朝向(圓形無意義)
    DateTime activation,   // 生效時刻
    uint color, bool risky, ulong actorID, ShapeDistance? shapeDistance)
```

**這一個結構就是我們要的全部東西**:形狀 + 位置 + 指向 + 時間。
逆向任何一個 module,本質上就是找出「哪段程式碼在什麼條件下 `new AOEInstance(...)`」。

## 5. Component — 機制類型詞彙

`BossMod/Components/` 底下是可重用的機制基底類別。module 幾乎只做兩件事:
挑一個 Component 繼承、餵它參數。因此 **Component 的型別本身就說明了機制種類**:

| Component | 機制 | 常見參數 |
|---|---|---|
| `SimpleAOEs` | 單純的讀條 AOE | `(AID, AOEShape)` |
| `GenericAOEs` | 需要自訂邏輯的 AOE | 覆寫 `ActiveAOEs()` |
| `SpreadFromIcon` | 分散(頭頂圖示) | `(IconID, AID, radius, delay)` |
| `StackWithIcon` | 集合分攤 | `(IconID, AID, radius, delay, minPlayers, maxPlayers)` |
| `GenericTowers` | 踩塔 | `Tower(pos, radius, minSoakers, maxSoakers, forbidden, activation)` |
| `SimpleKnockbacks` | 擊退/牽引 | `(AID, distance, kind, stopAfterWall)` |
| `GenericForcedMarch` | 強制位移 | `AddForcedMovement(target, dir, distance, time)` |
| `TankSwap` | 換坦死刑 | `(visualAID, tbAID, autoAID, ...)` |
| `Gaze` / `Exaflare` / `ChasingAOEs` / `Voidzone` / `Chains` / `LineOfSightAOE` | 視線 / 連鎖爆 / 追蹤 AOE / 毒圈 / 連線 / 遮蔽 | — |

`Kind.TowardsOrigin` = 牽引(往中心拉),預設 = 擊退(推開)。

## 6. StateMachine — 時間軸

`<Module>States.cs` 是一份 **完整的時間軸**,格式:

```csharp
Cast(id, (uint)AID.XXX, delay, castTime, "顯示名稱")
    .SetHint(StateMachine.StateHint.Raidwide)
    .ActivateOnEnter<SomeComponent>();
ComponentCondition<C>(id, delay, comp => comp.NumCasts != 0, "說明");
```

- `delay` 是 **距離上一個狀態的秒數**(相對值,不是絕對時間)。
- 把整串 delay 累加起來就是一條可用的攻略時間軸。
- `StateHint` 標了 `Raidwide` / `Tankbuster` / `Knockback` / `DowntimeStart`,
  可直接對應到我們攻略的「全屏」「死刑」「擊退」「無敵時間」標記。

## 7. ShapeDistance / AIHints — 「安全區」的表達

`BossMod/Util/ShapeDistance/`。`SD*` 系列(`SDCircle`、`SDInvertedCircle`、`SDCone`、
`SDRect`、`SDUnion`、`SDInvertedCross` …)描述的是 **禁止站位區**,
供插件的自動走位 AI 使用。

**這比 AOE 本身更有價值**:`AddForbiddenZone` 寫的是「這一招該站哪裡」的解法,
等同於插件作者的攻略結論。逆向時務必一併讀 `AddAIHints()`。

例:`hints.AddForbiddenZone(new SDInvertedCircle(c.Origin, 9f), act)`
= 「離中心 9m 以外都禁止」= 這招要貼中心站。
