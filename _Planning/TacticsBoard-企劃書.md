# FFXIV 戰術白板(Tactics Board)企劃書

> 版本:v0.2
> 日期:2026-07-21
> 定位:與現有「攻略閱讀工具」平行的第二個子專案,未來共用同一個入口目錄(index.html),但**本期開發不動現有攻略工具的任何檔案**。

---

## 一、專案概述

模擬球類比賽教練白板的**即時戰術討論工具**:指揮/團長在討論走位時,直接在俯瞰場地圖上拖曳兵棋、畫箭頭、放地毯(AOE 範圍),並可將多個盤面串成簡易時間軸動畫演示走位,取代口頭描述與靜態截圖。

### 與現有攻略工具的關係

| 項目 | 攻略閱讀工具(現有) | 戰術白板(本企劃) |
|---|---|---|
| 內容來源 | 預先製作的資料檔(唯讀) | 使用者即時編輯 |
| 使用情境 | 戰前預習、個人複習 | 團練中的即時討論、開荒解法推演 |
| 共用資產 | 場地定義格式、座標系、職能配色、SVG 繪製原語(arena.js 的 AOE/連線/箭頭) | 同左,抽出共用 |

兩專案未來目錄整合構想(僅供參考,本期不執行):

```
FFXIV-StrategyTool/
├── index.html            # 總入口:攻略庫 / 白板 兩大功能
├── guide.html            # 攻略閱讀(現有,不動)
├── board.html            # 戰術白板(新)
├── js/
│   ├── arena.js          # 攻略工具現有渲染引擎(不動)
│   └── board/            # 白板專用模組(新)
├── data/                 # 攻略資料(現有)
│   └── arenas/           # 場地定義庫(新,兩工具未來共用)
└── server/               # Phase 2:同步伺服器(新)
```

## 二、使用情境

1. **單機白板(Phase 1)**:指揮開啟網頁 → 選場地與階段 → 拖兵棋討論 → 透過 Discord 分享螢幕給團員看。零建置、雙擊即開,與現有攻略工具相同的技術基調。
2. **多人連線同步(Phase 2)**:指揮建立房間取得房號 → 團員輸入房號加入 → 指揮(或被授權者)的每個操作即時同步到所有人的瀏覽器。盤面可存於伺服器,下次團練直接開啟。

## 三、功能需求

### 3.1 場地系統

- **換場地**(低頻,換副本時):從場地庫選擇。場地為**純 SVG 程式繪製**,定義格式沿用攻略工具的 `arena` 結構並擴充:
  ```jsonc
  {
    "id": "o4s",
    "name": "次元的夾縫 歐米加零式:DELTA篇4層",
    "phases": [
      {
        "id": "p1", "name": "P1 艾克斯迪司",
        "shape": "circle",            // circle | rect | polygon
        "size": { "r": 100 },          // rect 用 w/h
        "waymarks": [ {"id":"A","x":0,"y":-95}, ... ],
        "deco": []                     // 選配:場地裝飾線(SVG path)
      },
      { "id": "p2", "name": "P2 ...", ... }
    ]
  }
  ```
- **換階段**(高頻):同場地內的階段以工具列下拉/分頁快速切換。**切換階段時保留兵棋位置**(可選「重置為預設站位」)。
- 場地庫為資料檔(`data/arenas/*.js`),新副本 = 新增一個場地定義檔,與攻略工具的資料驅動理念一致。

### 3.2 兵棋(Token)系統

| 類型 | 內容 | 說明 |
|---|---|---|
| 玩家 | MT/ST/H1/H2/D1-D4 固定 8 顆 | 沿用攻略工具配色(坦藍/奶綠/DPS紅)與圓形標記樣式 |
| BOSS | 1 顆預設,可增減 | 較大的紫色標記,可設定面向(朝向箭頭) |
| 小怪/機制物 | 自由新增 n 顆 | 可命名(如「觸手1」「黑洞」),可選色 |
| 場地標記 | A/B/C/D、1/2/3/4 共 8 顆 | 對應遊戲內可標註的點;支援**一鍵全部鎖定/解鎖**(鎖定後不可拖曳,避免討論時誤觸) |

- 所有兵棋可拖曳;點選後顯示選取框,可刪除(玩家/場地標記不可刪除,只能隱藏)。
- 鎖定機制:場地標記整組鎖定;其他兵棋可個別鎖定。

### 3.3 標註物(Marker)

- **常用標註物內建**:三角點名、分攤標記(集中)、死刑標記、擊退符號、禁止符號、數字/文字標籤。
- **可透過專案更新客製化**:標註物定義在 `data/board-markers.js` 資料檔中(名稱 + SVG 圖形),新增副本特有標註只需擴充該檔,不改程式。

### 3.4 箭頭指向物

| 類型 | 用途 | 參數 |
|---|---|---|
| 直線箭頭 | 直線移動、擊退方向 | 起點、終點(皆可拖曳調整) |
| 圓弧箭頭(順時針) | 繞場移動 | 圓心固定場地中心;半徑、起訖角度可拖曳調整 |
| 圓弧箭頭(逆時針) | 同上反向 | 同上 |

- 沿用攻略工具已驗證的「取樣點畫弧」實作(圓心鎖定場地中心,不會偏移)。

### 3.5 連線(Tether)

- 任兩個物件(兵棋↔兵棋、兵棋↔標註物、兵棋↔地毯)之間可建立連線。
- 連線跟隨兩端物件移動即時更新(對應黑洞拉球、羈絆線等機制)。
- 樣式:虛線,可選色(預設紫,同攻略工具)。

### 3.6 地毯(AOE 範圍)

**基本形狀**(放置後可拖曳移動、調整大小/角度):

| 形狀 | 參數 | 對應機制舉例 |
|---|---|---|
| 圓形 | 圓心、半徑 | 二連冰黃圈、暴雷 |
| 環形(月環) | 圓心、內外半徑 | 月環斬 |
| 長方形 | 中心、寬高、旋轉角 | 直線衝鋒、光束 |
| 扇形 | 頂點、朝向、張角、半徑 | 死亡吐息、觸手橫掃 |

**常見機制預設**(一鍵放置的複合物件):

| 預設 | 行為 |
|---|---|
| 集中分攤 | 分攤圖示 + 圓圈,可吸附到指定兵棋上跟隨 |
| 全員分散(玩家圓心圓形地毯) | 以每顆玩家兵棋為圓心各生成一個圓,跟隨玩家移動(對應二連火分散) |
| 死刑 | 死刑圖示吸附於目標兵棋(通常為 T) |
| 擊退 | 從指定點向外的放射箭頭組 |

- 顏色語意沿用攻略工具:火橘/冰黃/雷藍/暗紫/即死紅。
- 地毯亦可鎖定,避免討論走位時誤拖機制範圍。

### 3.7 時間軸(簡易動畫)

- 白板底部為時間軸列,由**關鍵影格(Keyframe)**組成:
  1. 「新增影格」= 複製當前盤面為新影格。
  2. 點擊時間軸上的影格 → 畫面切換至該影格盤面(兵棋位置以動畫過渡,沿用攻略工具的 CSS transition 手法)。
  3. 在任一影格上直接拖曳兵棋 = 編輯該影格。
- 每個影格可設定「與下一格的間隔秒數」(預設 1.5s,0.5s 步進)。
- **播放**:▶ 依序播放全部影格,兵棋平滑移動,形成走位動畫;可暫停、逐格。
- 影格可重新排序、複製、刪除。
- 時間軸上限暫定 30 格(單一機制的走位演示足夠,避免變成影片剪輯器)。

**物件的「同步到全部影格」模式**(常駐物件):

- 每個物件(兵棋/地毯/箭頭/標註/連線)可切換 **「逐格獨立」**(預設,不同影格可有不同位置/有無)或 **「同步模式」**。
- 進入同步模式的物件,在任一影格中拖曳/調整它時,**該次操作會立即套用到時間軸上所有影格**的對應物件(位置、大小、角度一起改),不需逐格重複調整。
- 適合固定不動的場地機制(如整場常駐的黑洞底圖、固定站位參考點);玩家走位這種「每格都不同」的物件則維持逐格獨立。
- 物件清單面板上以圖示標示目前是「逐格」或「同步」,並可一鍵切換;切換時**以當前影格的狀態覆蓋所有影格**,不做自動內插。

### 3.8 儲存與分享

| 方式 | Phase | 說明 |
|---|---|---|
| 本地自動保存 | 1 | localStorage 保存最近盤面,重開頁面不遺失;可另存多個具名盤面 |
| JSON 匯出/匯入 | 1 | 盤面(場地+兵棋+物件+時間軸)序列化為單一 .json 檔,傳給隊友匯入 |
| 伺服器儲存 | 2 | 盤面存於房間內,房間成員皆可載入;伺服器持久化(SQLite/檔案) |

**盤面 JSON 結構(單一事實來源,三種儲存方式共用)**:

```jsonc
{
  "version": 1,
  "arenaId": "o4s", "phaseId": "p1",
  "tokens":  [ { "id":"MT", "kind":"player", "x":0, "y":-20, "locked":false, "sync": false }, ... ],
  "objects": [ { "id":"ao1", "kind":"aoe-circle", "x":0, "y":30, "r":15, "color":"ice", "locked":false, "sync": true },
               { "id":"ar1", "kind":"arrow-arc", "radius":60, "start":140, "end":250, "dir":"cw", "sync": false },
               { "id":"te1", "kind":"tether", "from":"MT", "to":"ao1", "sync": false } ],
  "timeline": { "frames": [ { "snapshot": { /* 僅記錄 sync:false 的物件狀態 */ }, "holdSec": 1.5 } ] }
}
```

- `sync: true` 的物件**不進入每格快照**,其唯一狀態直接存在 `objects` 陣列本身,所有影格共用同一份;播放/切格時這類物件維持不變。
- `sync: false`(預設)的物件狀態才會被逐格記錄進 `timeline.frames[i].snapshot`。
- 切換 `sync` 開關時:false→true 以目前影格的值寫回 `objects`(拋棄其他影格中該物件的值);true→false 則把目前值複製成所有影格的初始快照值。

### 3.9 存取密碼(進入門檻)

- 白板開啟時先顯示密碼輸入畫面,輸入正確密碼(**寫死 `654321`**)才能進入操作介面。
- 用途是**擋掉不知情的人隨手打開**,不是真正的安全機制——請注意:
  - Phase 1(純靜態)下密碼判斷跑在前端 JS,任何人檢視原始碼都能看到明碼,只能防君子不防有心人。
  - Phase 2 建房/加入房間時,同一組密碼作為房間存取門檻,伺服器端也會驗證(比純前端稍微紮實一點,但仍是共用密碼,非帳號機制)。
- 驗證通過後以 `sessionStorage` 記住,同分頁內不用重複輸入;關閉分頁或新分頁需重新輸入。
- 之後若想改成「每個團隊自訂密碼」或「真正的帳號系統」,可視需求再升級,目前先滿足「全員共用同一組門檻密碼」的需求。

## 五、技術架構

### Phase 1:單機白板(純靜態)

- 與攻略工具相同:**純 HTML/CSS/JS,無建置流程**,`file://` 雙擊即開。
- 渲染:SVG(沿用攻略工具的座標系「中心原點、半徑 100」與繪製原語;白板專用互動邏輯獨立成 `js/board/` 模組,不修改現有 arena.js,必要的共用程式先以複製方式帶入,整合期再抽共用)。
- 狀態管理:單一 `BoardState` 物件(即上節 JSON 結構),所有操作 = 對 state 的變更 + 重繪。**這是為 Phase 2 鋪路的關鍵**:操作以「指令」(如 `{op:"move", id:"MT", x,y}`)形式套用,單機時直接執行,連線時廣播。

### Phase 2:多人連線同步

- **伺服器**:Node.js + WebSocket(ws 套件),極簡房間模型:
  - 建房 → 6 碼房號;加入 → 輸入房號。
  - 權限:房主預設唯一編輯者,可授權他人共同編輯;其餘為觀看者(收同步、不可操作)。
  - 同步:編輯者的操作指令廣播給全房;新成員加入時收完整快照。
  - 持久化:房間盤面定期/手動存檔至伺服器(SQLite 或 JSON 檔皆可,量小)。
- 前端不變:同一份 board.html,偵測「已連房」則將指令送伺服器,否則本地執行。
- 部署:一台小 VPS 或家用機即可(單房間流量極小)。

### 風險與對策

| 風險 | 對策 |
|---|---|
| Phase 2 同步衝突(兩人同時拖) | 單一編輯者模型直接迴避;共同編輯時「後到覆蓋」即可,白板不需 OT/CRDT |
| 時間軸快照體積 | 快照只存差異化必要欄位,30 格 × 幾十個物件,JSON 僅數十 KB,無壓力 |
| 觸控/手機操作 | 本期以桌面為主,手機僅保證「可觀看」;觸控編輯列為未來項目 |

## 七、確認事項紀錄(v0.2)

| # | 問題 | 決議 |
|---|---|---|
| 1 | 弧形箭頭圓心是否固定場地中心 | **維持固定場地中心**,不支援任意點為圓心(先這樣,未來有需求再擴充) |
| 2 | 時間軸與物件的關係 | **新增「同步模式」**:物件可標記為 sync,針對該物件的操作直接同步套用到所有影格,不需逐格調整(詳見 3.7) |
| 3 | Undo 範圍 | Phase 1 提供 20 步 Ctrl+Z;Phase 2 連線模式不提供跨人 Undo,維持原案 |
| 4 | Phase 2 部署環境 | **先以自家電腦部署**(區網或搭配 ngrok/frp 類工具對外,屆時再議) |
| 5 | 存取控制 | **新增密碼門檻**(3.9 節):全員共用密碼 `654321`,前端寫死 + Phase 2 伺服器端同步驗證 |

弧形箭頭圓心與 Undo 範圍維持原提案不變;時間軸同步模式與密碼門檻已納入本文件 3.7、3.9 節設計。
